## 简介

ListenStat（听时）读取系统「正在播放」媒体会话，统计**任意**会发布媒体会话的应用（音乐、播客、视频播放器、会暴露会话的浏览器等），在本地累计播放时长。系统没有媒体会话时无法记录。

- **Android**：通知使用权读取媒体会话（与控制中心媒体控件同源）
- **Windows**：桌面端（[`desktop/`](desktop/)）读取系统媒体控件（音量弹窗里的「正在播放」），可选托盘常驻与开机自启

- 按 **日 / 月 / 年** 查看，并可切换到 **任意一天、一个月或一年**：左右箭头、横向日期条，或点日期打开日历 / 月份 / 年份选择器
- **按应用** Top 20、**按内容标题** Top 20（标题取决于播放器是否写入媒体元数据；为空时记为应用名）
- 「正在听」卡片实时显示本段时长与今日累计；只有所选时段包含当前时刻时，才会把正在进行的时长计入统计
- **成就**（纯本地）：初次收听、累计 1 / 10 / 100 / 500 小时、连续 3 / 7 / 30 天、单日 3 小时、夜猫子（0–5 点收听）、50 个不同标题……只在打开或回到应用时根据本机数据计算，新解锁时轻提示
- **壁纸背景**：用系统照片选择器选一张图，可调模糊与柔化遮罩，卡片半透明叠在上面；随时可移除
- **备份 / 恢复**：导出为 JSON 文件，导入时自动合并去重
- **检查更新**：打开应用时（每天最多一次）或手动检查 GitHub 上的新版本，可在设置中关闭（与云端同步相互独立）
- **云端同步（可选，默认关闭）**：设置中开启后，向自建服务注册设备并同步各日收听合计；关闭后不发起任何同步网络请求。不上传壁纸

## 权限与隐私

| 权限 | 用途 |
| --- | --- |
| 通知使用权（Notification Listener） | 读取系统媒体会话，否则无法统计 |
| `INTERNET` | （1）可选：查询 GitHub Releases 是否有新版本；（2）可选：云端同步开启后访问自建同步 API |

- 默认所有记录只存在本机 Room 数据库（含应用包名、标题、艺术家/作者字段 `artist`、起止时间）
- **云端同步默认关闭**。关闭时不上传、不请求同步接口，行为与从前一致
- 开启云端同步后会上传：设备稳定 ID、可选显示名称，以及各日收听合计（`package` / `title` / `day` / `duration_ms`）。**不上传壁纸图片**、无广告或第三方统计 SDK
- 手机与 Windows 可通过**配对码**合并到同一账号（需两端都开启同步）；未配对时各设备仍是独立账号
- 更新检测与云端同步相互独立，只读取公开的版本信息
- 同步用的设备令牌保存在 EncryptedSharedPreferences（或等效私有存储），不会写入日志
- 壁纸通过系统照片选择器选取，复制到应用私有目录；备份文件通过系统文件选择器读写 —— **无需存储 / 相册权限**
- 不需要通知权限、无前台服务、无常驻通知
- 卸载应用即可清除全部数据

### 云端同步说明

1. 设置 →「云端同步」开关（默认关）→ 开启后自动注册并首次推送/拉取
2. 可选填写显示名称；同步开启期间改名会 PATCH 到服务器
3. 高级：可改服务器地址（默认 `https://jiketianxiawang.top`）。调试版允许 `http://IP` 做实验室测试；正式版仅 HTTPS
4. 拉取合并策略：按 `record_id`（由包名+标题+日期派生）取 **本地与远端时长的较大值**——若远端更大，仅补一条合成会话填补差额，**不会删除或缩短本机已有记录**
5. **配对**：一端生成配对码，另一端输入，即可把手机与电脑合并到同一账号（服务端已支持；手机端配对入口随后续小版本提供）

## 使用

1. 安装 APK（Android 8.0+）
2. 打开 App →「去开启通知使用权」→ 开启 ListenStat
3. 用任意会发布系统媒体会话的 App（音乐、播客、视频等）正常播放一段时间
4. 回到 ListenStat，用 日 / 月 / 年 和日期条查看统计；底部悬浮按钮切换「统计 / 成就 / 设置」

## 备份与恢复

1. 设置 →「备份 / 恢复」→「导出」，在系统文件选择器中选择保存位置（例如下载目录或网盘），得到 `ListenStat-backup-日期.json`
2. 换机或重装后：设置 →「备份 / 恢复」→「导入」，选择该文件
3. 导入是**合并**：已存在的记录（同一开始时间 + 应用包名 + 标题）会被跳过，不会重复；成就保留最早的解锁时间；自动检查更新、壁纸模糊/遮罩等设置一并恢复（壁纸图片本身不包含在备份中）

## 限制

- 支持 Android 与 Windows；iOS 无法同等实现
- 依赖系统媒体会话（Android MediaSession / Windows 系统媒体控件）；播放器不发布会话时无法统计
- 标题明细依赖播放器写入 `MediaMetadata`；为空时回退为应用名
- 统计的是媒体会话处于 Playing 的墙钟时间

## 省电

- **事件驱动**：只在播放 / 暂停 / 切换曲目或章节 / 会话消失时记录，无 15 秒轮询、无定时唤醒
- 播放中只在内存里记开始时间，结束时写一次数据库；不足 3 秒的片段直接忽略
- 意外被杀后，下次启动会用系统记录的进程退出时间补全上一段（不臆造时长）
- **无前台服务、无常驻通知、无唤醒锁**；界面只在前台可见且正在播放时每秒刷新计时
- 成就只在打开 / 回到应用时计算，没有任何后台任务；联网默认只有每天最多一次的版本检查（可关闭）；云端同步另需手动开启
- 提示：只有当系统频繁杀掉 ListenStat、导致统计中断时，再在「电池优化」里把它设为不受限制

## 构建

```bash
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest   # 含数据库迁移校验
```

发布版签名从 `~/.gradle/gradle.properties` 或环境变量读取（不在仓库中）：

```properties
LISTENSTAT_KEYSTORE=/path/to/listenstat.keystore
LISTENSTAT_KEYSTORE_PASSWORD=...
LISTENSTAT_KEY_ALIAS=...
LISTENSTAT_KEY_PASSWORD=...
```

然后 `./gradlew :app:assembleRelease`。未配置时会回退到本机 debug 签名（无法覆盖安装正式签名的版本）。
